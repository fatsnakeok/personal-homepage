## 为什么自研？

虽然市面上有成熟的AI代码审查工具，但我们选择自研，原因如下：

1. **数据安全**：代码完全在内网流转
2. **定制化**：适配我们的编码规范和业务场景
3. **成本控制**：长期来看比SaaS更经济
4. **技术积累**：团队学习AI应用开发

## 核心功能

### 1. 智能代码审查

AI会从以下维度审查代码：

```python
review_dimensions = [
    "代码规范",      # 命名、格式、注释
    "潜在Bug",       # 空指针、资源泄漏
    "性能问题",      # N+1查询、大循环
    "安全风险",      # SQL注入、XSS
    "可维护性",      # 复杂度、重复代码
]
```

### 2. 自动生成审查报告

每份PR都会生成结构化报告：

```markdown
## 代码审查报告

### 总体评分：85/100

### 发现问题（3个）
1. ⚠️ [性能] 第45行存在N+1查询问题
2. 🔴 [安全] 第78行存在SQL注入风险
3. 💡 [建议] 第120行可简化为Stream API

### 亮点（2个）
1. ✅ 异常处理完善
2. ✅ 单元测试覆盖率高
```

### 3. 与GitLab集成

审查结果直接显示在MR评论区：

```java
// 自动评论示例
gitLabApi.createMergeRequestComment(
    projectId,
    mergeRequestId,
    "AI审查完成，发现3个问题需要关注"
);
```

## 最佳实践

### Prompt设计

我们总结了一套有效的Prompt模板：

```
你是一位资深代码审查专家。请审查以下代码变更：

【代码差异】
{diff_content}

【审查重点】
1. 代码规范
2. 潜在Bug
3. 性能问题
4. 安全风险

【输出格式】
按严重程度分类，给出具体行号和修改建议。
```

### 误报处理

对于误报，我们采用反馈学习机制：

1. 工程师标记误报
2. 收集误报样本
3. 定期微调模型
4. 更新规则库

## 遇到的坑

### 1. 上下文长度限制

初期使用4K上下文模型，审查大文件时被截断。解决方案：

- 分段审查 + 结果聚合
- 升级到32K上下文模型

### 2. 审查延迟

高峰期审查排队导致延迟超过10分钟。解决方案：

- 引入任务队列
- 增加Worker实例
- 优先级调度
