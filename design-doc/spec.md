# 个人网站需求分析文档

## 1. 项目概述

基于 GitHub Pages 搭建一个个人网站，用于展示个人文章、简历与座右铭，整体风格追求清新扁平化。

## 2. 技术选型

| 项目 | 选型 | 说明 |
|------|------|------|
| 托管平台 | Gitee Pages | 国内访问速度快，免费静态站点托管，支持自定义域名 |
| 构建工具 | VitePress | 将 Markdown 文章转化为静态页面，Vue 生态支持 |
| 样式方案 | Tailwind CSS | 实现清新扁平化风格，快速开发 |
| 文章格式 | Markdown | 便于撰写与版本管理 |

## 3. 功能需求

### 3.1 网站结构

网站分为四个主要页面：
- **首页**：展示 logo、背景图与座右铭
- **博客**：展示文章列表，每行一篇文章
- **简历**：展示个人简历
- **关于**：关于网站与个人的介绍

### 3.2 首页

- **布局方式**：全屏背景图 + 居中内容
- **展示内容**：
  - 网站 logo（圆形，位于页面上部）
  - 网站名称："空杯成长笔记"
  - 座右铭："空杯成长必经"（或其他个性化文字）
  - 导航按钮（首页、博客、简历、关于）
- **背景图**：清新风景图，建议选择山水、森林、天空等自然场景
- **交互行为**：
  - 点击导航按钮跳转至对应页面
  - 页面滚动时内容保持居中
- **响应式**：适配所有屏幕尺寸，内容始终居中显示

### 3.3 博客

- **布局方式**：单列表布局，每行一篇文章，垂直排列
- **文章卡片内容**：
  - 文章标题
  - 发布日期
  - 文章摘要（自动截取前 N 个字符）
  - 封面图 / 缩略图（可选）
  - 标签 / 分类
- **左侧侧边栏**：
  - 个人头像
  - 座右铭："空杯成长笔记"
  - 标签云 / 分类导航
- **交互行为**：
  - 点击卡片跳转至文章详情页
  - 支持按标签 / 分类筛选
  - 支持滚动加载更多（或分页）
- **响应式**：
  - 桌面端：左侧侧边栏 + 右侧文章列表
  - 平板 / 移动端：侧边栏折叠为顶部抽屉，文章列表全屏显示

### 3.4 简历

- **布局方式**：单页简历，清晰的章节划分
- **内容模块**：
  - 个人信息（姓名、联系方式、邮箱、GitHub 等）
  - 教育经历
  - 工作经历
  - 技能栈
  - 项目经验
  - 证书 / 奖项（可选）
- **交互行为**：
  - 支持下载 PDF 版本
  - 章节可折叠 / 展开（可选）
- **响应式**：移动端自适应布局，保证阅读体验

### 3.5 关于

- **布局方式**：简洁的单页内容
- **内容模块**：
  - 网站介绍
  - 个人简介
  - 联系方式
  - 技术栈说明
- **交互行为**：
  - 点击链接跳转至对应平台

### 3.6 文章详情页

- Markdown 渲染为 HTML
- 支持代码高亮
- 显示发布日期、标签等元信息
- 返回首页导航
- 左侧侧边栏（与博客页一致）

## 5. 视觉风格

### 5.1 设计参考

首页风格参考以下布局：
- 全屏背景图，营造沉浸式体验
- 居中内容，包含 logo、网站名称、座右铭与导航按钮
- 深色半透明背景的导航按钮，保证可读性

### 5.2 清新扁平化设计原则

- **无阴影 / 极少阴影**：卡片和按钮不使用厚重投影，仅用细微边框或微阴影区分层级
- **纯色填充**：图标和按钮使用纯色，无渐变、无光泽
- **圆角**：卡片和按钮采用适度圆角（4px - 8px），柔和但不夸张
- **留白**：充足的间距与留白，避免视觉拥挤

### 5.3 色彩方案

| 用途 | 色值建议 | 说明 |
|------|----------|------|
| 主色 | `#4A90D9` 或 `#5B8DEF` | 清新蓝，用于标题、链接、按钮 |
| 辅助色 | `#6AC4A0` 或 `#7EC8A0` | 清新绿，用于标签、强调 |
| 背景色 | `#F7F9FC` 或 `#FAFBFC` | 浅灰白，干净通透 |
| 卡片背景 | `#FFFFFF` | 纯白 |
| 正文色 | `#2C3E50` 或 `#333333` | 深灰，阅读舒适 |
| 次要文字 | `#8899AA` 或 `#999999` | 浅灰，用于日期、摘要 |
| 导航按钮 | `rgba(0, 0, 0, 0.5)` | 半透明深色，保证在背景图上的可读性 |

### 5.4 字体

- 标题：无衬线字体（如 `Inter` / `Noto Sans SC`）
- 正文：无衬线字体，行高 1.6 - 1.8，保证阅读体验
- 代码：等宽字体（如 `Fira Code` / `JetBrains Mono`）

## 6. 响应式设计

### 6.1 断点设置

| 断点 | 设备类型 | 布局调整 |
|------|----------|----------|
| < 768px（移动端） | 手机 | 侧边栏折叠为顶部抽屉，文章列表全屏显示 |
| 768px - 1024px（平板） | 平板 | 侧边栏可折叠，文章列表自适应宽度 |
| > 1024px（桌面端） | 桌面 | 左侧固定侧边栏，右侧文章列表 |

### 6.2 首页响应式

- 所有屏幕尺寸下内容始终居中显示
- 导航按钮在移动端变为底部导航栏

## 7. 非功能需求

| 项目 | 要求 |
|------|------|
| 加载性能 | 首屏加载 < 3s，图片懒加载 |
| SEO | 语义化 HTML，合理的 meta 标签 |
| 无障碍 | 图片 alt 属性，键盘可导航，对比度达标 |
| 浏览器兼容 | 支持主流现代浏览器最近两个大版本 |
| 可维护性 | 文章以 Markdown 文件管理，新增文章无需修改代码 |

## 8. 内容管理

- 文章存放于 `posts/` 目录，每篇文章为一个 Markdown 文件
- 文章通过 Front Matter 声明元信息：

```yaml
---
title: 文章标题
date: 2026-06-10
tags: [标签1, 标签2]
cover: /assets/images/cover.jpg
excerpt: 文章摘要
---
```

- 新增文章流程：编写 Markdown → 推送至 GitHub → 自动构建部署

## 9. 部署方案

1. 代码托管于 GitHub 仓库
2. 启用 GitHub Pages，选择分支或 GitHub Actions 自动部署
3. 可选：绑定自定义域名

## 10. 发布 CI/CD

### 10.1 目标

实现代码推送后自动构建与发布，无需手动操作，确保每次变更都能快速、可靠地部署到 GitHub Pages。

### 10.2 流程设计

```
代码推送 / PR 合并 → GitHub Actions 触发 → 安装依赖 → 构建站点 → 部署至 GitHub Pages
```

### 10.3 触发条件

| 事件 | 分支 | 动作 |
|------|------|------|
| push | `main` | 构建并部署到生产环境 |
| pull_request | `main` | 仅构建，预览效果（可选） |

### 10.4 CI/CD 流水线步骤

1. **触发**：监听 `main` 分支的 push 事件
2. **环境准备**：
   - 检出代码（`actions/checkout`）
   - 安装 Node.js
   - 安装项目依赖
3. **质量检查**（可选）：
   - Lint 检查（ESLint / Stylelint）
   - Markdown 格式校验
   - 死链检测
4. **构建**：
   - 执行站点构建命令，生成静态文件到输出目录
5. **部署**：
   - 使用 `actions/deploy-pages` 将构建产物部署到 GitHub Pages
6. **通知**（可选）：
   - 部署成功 / 失败时通过邮件或 GitHub Notification 通知

### 10.5 GitHub Actions 工作流配置文件

- 配置文件路径：`.github/workflows/deploy.yml`
- 关键配置项：
  - `permissions`: 授予 `contents: read` 和 `pages: write` 权限
  - `concurrency`: 同一分支仅允许一个部署任务运行，避免冲突

### 10.6 环境变量

| 变量名 | 用途 | 示例 |
|--------|------|------|
| `NODE_VERSION` | Node.js 版本 | `20` |
| `BUILD_DIR` | 构建输出目录 | `dist` |

### 10.7 回滚策略

- GitHub Pages 保留历史部署版本，可通过 GitHub Actions 重新运行历史工作流回滚到先前版本
- 紧急情况下，可 revert 对应的 commit 并重新推送触发部署
